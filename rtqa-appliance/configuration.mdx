This page is generated from the settings registry of the Aitrium RTQA appliance release it documents, so it lists exactly the settings that release reads. On an appliance, `sudo /opt/aitrium/rtqa/bin/aitrium-rtqa settings reference` prints the same reference for the installed release.

Settings live in the appliance's configuration file, `/opt/aitrium/rtqa/.env`. Change them in the console (**Settings → Configuration**, for administrators) or in the setup wizard. Both validate the value, keep a timestamped backup, and show what changed. To edit the file by hand, edit it as the service account: `sudo -u aitrium-rtqa nano /opt/aitrium/rtqa/.env`. Restart the services after a change.

Some settings are root's, not the `.env`'s, on an appliance with a service account: the data locations, the reviewer proxy's port and address, and the outbound proxy and CA used for updates. Change those by running the installer again with the matching option. See [The service account](/rtqa-appliance/install#the-service-account).

Two things to know before you change these settings:

- **Data locations.** `--state-dir`, `--received-dir`, and `--staging-dir` (and the matching settings) set where the appliance keeps data. They do **not** move data that is already there. The installer does not move existing data; to move it, follow [Changing data locations](/rtqa-appliance/operations#changing-data-locations).
- **A proxy that needs a password.** Use `RTQA_NETWORK_PROXY_URL_FILE`, not an inline URL with credentials. The installer records an inline proxy URL only when it carries no credentials, so updates run by root would not use it. Keep the file owned by root and readable by the service account (`root:aitrium-rtqa`, mode `0640`).

**How to read the tables.**

- Each key is named for its purpose under a group prefix, for example `RTQA_SITE_*` for the appliance's identity to Aitrium and `RTQA_SIGNIN_*` for reviewer sign-in.
- **Was** is the key's older name. Old names still work for two releases. `aitrium-rtqa settings check` reports any your file still uses, and `aitrium-rtqa settings migrate-env --apply` rewrites them, keeping a `.env.pre-rename` backup.
- Units are in the key: `_S` seconds, `_MS` milliseconds, `_HOURS`, `_DAYS`, `_PCT` percent, `_GB` gigabytes (10^9 bytes). `_DIR` is a folder and `_FILE` a file. Where a `_SECRET_FILE` or `_PASSWORD_FILE` variant exists, prefer it to the inline value.
- `<work dir>` is the work directory, `/opt/aitrium/rtqa` by default.

<Note>
  The installer writes `RTQA_DATA_RECEIVED_DIR=<work dir>/inbox` for every new install. The registry default below, `<work dir>/source`, applies only when the key is missing from the file altogether.
</Note>

| `RTQA_WORKER_LAUNCH_MODE` | Set by the launchers: direct, managed_detached or systemd. |
| `RTQA_MODEL_FILE` | Selected model file name (installer). |
| `RTQA_MODEL_PATH` | Absolute model path passed to the model server (launcher). |
| `RTQA_CONTEXT_SIZE` | Model context size passed to the model server (launcher). |
| `RTQA_LLAMA_PORT` | Model server port (launcher). |
| `RTQA_LLAMA_CPP_BIN` | Model server binary (launcher). |
| `RTQA_BIN_DIR` | Installed binaries directory (installer). |
| `RTQA_PERSISTENCE_AUTO_MIGRATE` | Developer only: migrate the state database on start. |
| `RTQA_ASSISTANT_HARNESS` | Developer only: assistant evaluation harness selection. |
| `RTQA_REVIEWER_USER_ID / _ORG_ID / _SITE_ID` | Developer only: local reviewer identity when no proxy injects one. |
