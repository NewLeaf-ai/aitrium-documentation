## Overview

The Integrations page allows organization administrators to manage data transfer integrations, credentials, and user permissions. Integrations are accessed at **Dashboard → Integrations**.

Each integration card displays:
- Integration name
- Credential type (**Cloud Credentials** or **Local Config**)
- Number of sites using the integration

Click on any integration card to manage its settings.

<img src="/images/integrations/integrations_page.png" alt="Integrations page showing list of configured integrations" style={{borderRadius: '8px'}} />

### What if I don't see any integrations?

If no integrations appear, your organization hasn't been set up with any data transfer integrations yet. Contact support at [contact@aitriumos.com](mailto:contact@aitriumos.com) to request integration setup.

## Credential Groups

Credential groups allow you to manage different sets of credentials within the same integration. This is useful when:

- Different sites require different connection endpoints or credentials
- You want to segregate credentials for security or organizational reasons
- Different trials need to route data through different systems

<img src="/images/integrations/integration_details_page_credential_groups.png" alt="Integration details page showing credential groups in the left sidebar" style={{borderRadius: '8px'}} />

### Key Features

- **Multiple Groups**: Create multiple credential groups per integration
- **Independent Credentials**: Each group has its own connection configuration
- **Trial Linking**: Link trials to a credential group to control which credentials are used for data transfers
- **Per-Site User Access**: Control which users at each site can access the integration, per trial

### Creating a Credential Group

1. Open an integration from the main Integrations page
2. Navigate to the **Credential Groups** tab
3. Click **Create New Group** in the left sidebar
4. Provide:
   - **Group Name**: A descriptive name for the credential group
   - **Description** (optional): Additional context about the group's purpose
5. Click **Create** to save the new group

<img src="/images/integrations/new_credential_group.png" alt="Create new credential group dialog" style={{borderRadius: '8px'}} />

### Editing a Credential Group

1. Select the credential group from the left sidebar
2. Click the **Edit** button (pencil icon)
3. Update the group name or description
4. Click **Save** to apply changes

### Deleting a Credential Group

1. Select the credential group to delete
2. Click the **Delete** button (trash icon)
3. Confirm the deletion in the dialog

<Note>
You must have at least one credential group per integration. The last group cannot be deleted.
</Note>

## Managing Credentials

Each credential group has a **Credentials** tab where you configure the connection details for that group.

### Viewing Current Credentials

1. Select a credential group from the left sidebar
2. The **Credentials** tab displays all configuration fields
3. Sensitive fields (passwords, private keys) display a **"Stored securely"** badge — values are never shown in plain text

### Updating Credentials

1. Select a credential group
2. Click **Edit** to enter edit mode
3. Modify the credential fields as needed:
   - **Text fields**: Enter alphanumeric values
   - **Number fields**: Enter numeric values only
   - **Boolean fields**: Toggle on/off
   - **Secret fields**: Enter passwords (masked on input)
   - **File fields**: Upload key files or certificates
4. Click **Save** to publish changes
5. Click **Cancel** to discard unsaved changes

### How Credential Updates Propagate

When you update credentials:
- Changes are automatically published to all sites assigned to the credential group
- Credentials are re-encrypted with each site's encryption key before distribution
- The system tracks all credential updates in the [Audit Log](/aitrium-admin/audit-logging)

<Warning>
Credential updates affect all trials and users linked to this credential group. Ensure credentials are correct before saving.
</Warning>

## SFTP Configuration

When an integration uses SFTP for data transfer, credential groups contain the following configuration fields:

| Field | Required | Description |
|-------|----------|-------------|
| **Host** | Yes | SFTP server hostname or IP address |
| **Port** | Yes | SFTP server port (typically 22) |
| **SFTP Username** | Yes | Authentication username |
| **SFTP Password** | Yes | Authentication password |
| **Root Directory** | No | Base directory path on the SFTP server. If omitted, the default directory is used. |
| **Private Key (RSA)** | No | RSA private key for key-based authentication. Paste the full PEM-encoded key in OpenSSH format. ECDSA and PuTTY `.ppk` formats are not supported. |
| **Private Key Password** | No | Passphrase for the private key, if the key is encrypted. |

<Note>
When both password and private key are provided, key-based authentication takes precedence.
</Note>

## Credential Encryption

All integration credentials are encrypted at rest using organization-level encryption keys managed through a Key Management Service (KMS).

### Owning Organization

Your organization owns the credential group and its encryption keys. Credentials are encrypted with your organization's KMS key before storage — they are never stored in plaintext.

### External Participating Sites

When external provider sites are assigned to a credential group through trial linking:

- Credentials are re-encrypted with site-level keys for secure distribution
- Each site receives only the credentials relevant to their assignment
- Credential transport uses session-derived encryption for additional security

This ensures that credentials are never transmitted in plaintext, and each participant only has access to the credentials they need.

## Managing Trial Access

Integration permissions are managed at the trial level. Each credential group has a **Trials** tab where you link trials and control per-site user access.

### Permission Hierarchy

Permissions follow a trial-scoped hierarchy:

**Integration → Credential Group → Trial → Site → Users**

- An integration has one or more **credential groups**, each with its own connection configuration
- Each credential group can be linked to one or more **trials**
- Different trials can use different credential groups — even for the same site. This means a site can have separate credentials for each trial it participates in.
- At each site, you control which **users** have access — either all site users or a selected subset

### Linking a Trial to a Credential Group

1. Select a credential group from the left sidebar
2. Navigate to the **Trials** tab
3. Click **Add Trial**
4. Search for and select the trial from the list

<Note>
Trials already linked to this credential group are excluded from the search results. Credentials must be configured before you can add trials.
</Note>

### Per-Trial Credential Groups

Different trials can be linked to different credential groups, even when they share the same sites. This allows you to:

- Route data for Trial A through one SFTP endpoint and Trial B through another
- Use separate credentials for different sponsors or data destinations
- Isolate trial data flows without creating duplicate sites

When the same site participates in multiple trials with different credential groups, each trial's data transfers use the credentials from its linked credential group.

### Trial Overview

Once trials are linked, the Trials tab displays each trial as a collapsible row:

- **Trial name** with site count and active/inactive status
- **Readiness indicators**:
  - Green dot — Site is transfer-ready (credentials and users configured)
  - Red dot — Site is blocked (missing credentials or user configuration)
  - Summary: "N sites not ready" when blocked sites exist
- **Header metrics**: Number of trials linked and total access patterns configured

Expand a trial to see all sites and their access configuration.

<img src="/images/integrations/credential-group-trials-tab.png" alt="Credential group Trials tab showing linked trials with site readiness indicators" style={{borderRadius: '8px'}} />

### Managing Site Access

Click **Manage access** on any site within a trial to configure user permissions:

**Access Modes:**

| Mode | Description |
|------|-------------|
| **All site users** | Every user at the site automatically has access to the integration for this trial. New users added to the site will inherit access. |
| **Selected users** | Only explicitly chosen users have access. You must add users individually. |

**In "Selected users" mode:**
- Search for users by name
- Click **Add** to grant a user access
- Click **Remove** to revoke a user's access
- The drawer shows users split into "Has Access" and "No Access" sections

<img src="/images/integrations/manage-site-access-drawer.png" alt="Site access management drawer showing access mode selection and user list" style={{borderRadius: '8px'}} />

### Removing a Trial

1. Expand or hover over the trial in the Trials tab
2. Click the dropdown menu on the trial header
3. Select **Remove Trial**
4. Confirm the removal

Removing a trial from a credential group revokes all associated user access for that trial.

## Managing Access from Trials

In addition to the Integrations page, admins can manage integration access directly from a trial's detail page. This is useful when you're working within a trial and want to configure site access without navigating to the Integrations section.

1. Navigate to **Dashboard → Projects → [Trial Name]**
2. Switch to the **Sites** tab
3. Each site row displays an **Access** column:
   - Shows the number of users with access (e.g., "3 Users")
   - Or **"Set Access"** if no permissions are configured yet
4. Click the access count or select **Manage Access** from the row's dropdown menu
5. The site access drawer opens — the same interface described in [Managing Site Access](#managing-site-access) above

<img src="/images/integrations/project-sites-access-column.png" alt="Trial sites tab showing the Access column with user counts and Manage Access action" style={{borderRadius: '8px'}} />

<Note>
Both entry points — the Integrations page and the Trial sites tab — manage the same underlying permissions. Changes made in one location are immediately reflected in the other.
</Note>

## Integration Logs

The Integration Logs tab provides execution logs showing when the integration has run and whether it succeeded or failed. This is useful for monitoring integration health and debugging issues.

### Log Analytics

The **Overview** tab provides a visual summary of integration execution history, including:
- Time series chart of success, warning, and failure events
- Recent activity list (last 10 events)
- Summary metrics: total events, success rate, error count, warning count

The **Errors** tab breaks down failures by category:
- **Authentication** — credential or permission issues
- **Connection** — network or timeout failures
- **Configuration** — setup or path issues
- **Transfer** — upload/download failures
- **Validation** — format or schema errors

<img src="/images/integrations/integration-log-analytics.png" alt="Integration log analytics showing execution metrics and error breakdown" style={{borderRadius: '8px'}} />

### Execution Details

The **Details** tab shows a chronological table of all integration executions:

| Column | Description |
|--------|-------------|
| **Timestamp** | When the execution occurred |
| **Action** | What the integration performed |
| **Status** | Success or failure |
| **Details** | Additional context about the execution |

The table is searchable and sortable by timestamp (default: newest first). Use the time range filter (1 day, 7 days, 30 days) to narrow results.

### Troubleshooting with Logs

- Identify when an integration last ran successfully
- Diagnose technical failures or connection issues
- Monitor integration performance and reliability
- Debug data transfer problems

## Common Tasks

### Granting a User Access to a Trial's Integration

1. Navigate to **Integrations** → Select the integration
2. Select the **Credential Group** linked to the trial
3. Go to the **Trials** tab and expand the trial
4. Click **Manage access** on the relevant site
5. Set the access mode to **Selected users** (if not already)
6. Find and **Add** the user

Alternatively, navigate to **Projects → [Trial] → Sites** tab and click **Manage Access** on the site row.

### Rotating Integration Credentials

1. Navigate to **Integrations** → Select the integration
2. Select the **Credential Group** to update
3. Go to the **Credentials** tab and click **Edit**
4. Update the credential fields with new values
5. Click **Save**
6. Verify the update in the [Audit Logs](/aitrium-admin/audit-logging) page

### Connecting a New Trial to a Credential Group

1. Navigate to **Integrations** → Select the integration
2. Select the **Credential Group** (or create a new one)
3. Ensure credentials are configured on the **Credentials** tab
4. Go to the **Trials** tab and click **Add Trial**
5. Search for and select the trial
6. Expand the trial and configure site access for each site

### Restricting Access to Specific Users at a Site

1. Navigate to the credential group's **Trials** tab
2. Expand the trial containing the site
3. Click **Manage access** on the site
4. Change the access mode from **All site users** to **Selected users**
5. Add only the users who should have access
6. Users not explicitly added will lose access

## Troubleshooting

### Problem: Can't See Any Integrations

**Solution**: Your organization may not have integrations configured. Contact support at [contact@aitriumos.com](mailto:contact@aitriumos.com) to set up integrations.

### Problem: Can't Update Credentials

**Possible Causes**:
- Required fields are missing
- Invalid values entered (e.g., text in a number field)
- Insufficient permissions

**Solution**: Check that all required fields are filled and valid. Ensure you have administrator permissions.

### Problem: Can't Add a Trial to a Credential Group

**Possible Causes**:
- Credentials have not been configured yet for the group
- The trial is already linked to this credential group

**Solution**: Configure credentials on the **Credentials** tab first. Check whether the trial is already linked.

### Problem: Site Shows as "Blocked" (Red Dot)

**Possible Causes**:
- Credentials are missing or incomplete for the credential group
- No users have been granted access at the site

**Solution**: Verify credentials are configured on the **Credentials** tab. Click **Manage access** on the blocked site and ensure at least one user has access.

### Problem: Credential Updates Not Taking Effect

**Solution**:
- Verify the update was successful in the [Audit Logs](/aitrium-admin/audit-logging) page
- Ensure the trial's sites are assigned to the correct credential group
- Contact support if the issue persists

### Problem: Integration Execution Failures

**Solution**:
- Check the **Logs** tab on the integration detail page for error messages
- Review recent credential changes in [Audit Logs](/aitrium-admin/audit-logging) that might have caused issues
- Verify network connectivity to the integration endpoint
- Contact support with the error details from the Integration Logs

For audit log questions, see [Audit Logging](/aitrium-admin/audit-logging).
